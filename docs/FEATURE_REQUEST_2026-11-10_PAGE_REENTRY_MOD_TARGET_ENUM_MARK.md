## 1 · Remember last module page (owner request)

Introduce **Global Settings → Display/UI → Remember Module Page**, default **Off** for backward compatibility. When enabled, leaving a module and re-entering the SAME module instance resumes on the last valid page *by stable page name*. Scope every remembered page by actual container/instance identity, e.g. track slot + component + loaded module identity; Master FX bus and Send A/B each have **separate namespaces**, not one global key. Prefer session-only memory initially, not a new on-disk state format; the On/Off preference itself persists. Manual return from a browser and explicit `restorePageName` always outrank fallback memory. Invalid/removed pages land on the normal first page. Opening a different module at the same position must not inherit its predecessor's page. No auto-firing buttons, navigating into a menu, or revisiting a destructive action by restoring a page. Opt-out should preserve existing first-page behavior.

Acceptance: cover Track 1/2 same module, module replacement, synth/FX/MIDI FX, Master FX, both sends, two instances, changes in page order, explicit one-shot restore, new/old module versions, Settings Off, Back/Exit and no accidental parameter writes; no extra DSP reads in draw path. Screen-reader announcement matches restored page.

## 2 · Modulation target occupancy (owner request)

In the common target-picker / parameter lists, display a tiny fixed-position mark or compact integer when an item is **already a target of other currently configured modulation**. Preferred readable representation on 128×64: a single unobtrusive dot for one, `2` for two, `3+` for three or more; choose only after pixel-render tests. Keep this **separate** from the current selection cursor and from the existing * for live enum value. Target source count is per exact `(slot/bus instance, component, parameter)`, not only short labels. Exclude disabled/unassigned/invalid routes from active count; if the product decides to show configured-but-disabled routes, use a different visual state and state it in help. Avoid double-counting one source, but allow two distinct LFOs on the same target to count as two. Preserve semantic text for TTS and selected rows. Update after mappings/presets/morphs and delete. No DSP/audio-thread allocations.

The generic backend is upstream Schwung. DJTTTO, WETTT and TTTUNNEL only need their own UI adapters if they bypass the Schwung picker; do not duplicate the host aggregation logic or expose private presets/FX algorithms in an upstream PR.

## 3 · Move active-value enum asterisk into a LEFT-fixed gutter (owner request)

**Confirmed upstream Schwung host rendering**: `enum_list.mjs` places `*` as a `getValue` at right; `menu_layout.mjs` budgets label and value columns independently, with scrolling/truncation. A safe patch should add a **narrow fixed leading marker gutter** to this enum-picker presentation (or a reusable optional `getLeadingMark` API on `drawMenuList`). Print the `*` before the option text, with a reserved width and correct selected-row foreground color. This must remain pinned while a long selected label scrolls; **not** merely prefix the scrolled text (`'* ' + name`), which could scroll the marker off-screen. Reserve equal gutter for all rows; text never overlaps the fixed glyph. Do not move other semantic right-hand values in unrelated menus or modify the existing dirty-preset mark. Preserve `markIndex` vs `index` and picker vs peek behavior.

Tests: 1/2/many options, long 128px value and scrolling, selected vs marked different rows, mark stays fixed during label scroll, inversion, no clipped pixels, unchanged TTS and Back semantics, enum picker + LFO target list + presets where relevant. Use the existing framebuffer harness `tests/host/test_enum_picker_chrome.sh`; compare rendered PNGs where feasible. Given clear shared-host ownership, first submit an isolated PR from **jorgeuribera/schwung** to **charlesvestal/schwung**, after device/CI acceptance. No direct upstream push or unsolicited changes to other projects.
